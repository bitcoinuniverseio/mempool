# Optional bounded native address reader

The Electrum backend retains its existing TCP reader by default. `ELECTRUM.ADDRESS_HTTP_URL` has no default and is deliberately absent from the ordinary sample configuration. Enable it only in an independently qualified profile for the same operated native reader that serves the configured TCP endpoint. The value must be a bare loopback HTTP origin, without credentials, path, query or fragment. There is no use of `ESPLORA.REST_API_URL`, redirect, proxy or fallback.

The candidate Signet serving role was observed on I2 as `universe-explorer-electrs-signet.service`, user `universe-electrs`, with HTTP `127.0.0.1:3022` and TCP `127.0.0.1:50013` in the same process and Signet database. Its binary SHA256 is `2620dd9094f36be75e7f18e9a75cd8eb0db4d183447b55c0ae5dbac9db7868e9`. The existing I1 source checkout is clean at `141215c349d5cfbabf8f2b925f3dcea59fed0510`; its `src/rest.rs` SHA256 `ed9b91c9e469a233176cbad70c2ba6091b1c4fc85d43100dab053cbd6cab6606` matches the [pinned upstream source](https://github.com/mempool/electrs/blob/141215c349d5cfbabf8f2b925f3dcea59fed0510/src/rest.rs). A complete deployed binary build manifest was unavailable, so binary/source build parity and full native acceptance remain unqualified.

Only these ordinary address methods select the optional reader:

- Summary: native `GET /address/:address`, exact safe integer counts and satoshi sums. Repeated bodies must agree, and funded-minus-spent balances must match two existing TCP `get_balance` observations after Core validates the address. Cumulative turnover is not capped to the live supply; unsafe integers are rejected.
- History: native `GET /address/:address/txs?max_txs=10`, followed by the same route with `&after_txid=:cursor`. Each public API read remains at most ten transactions, with no full history scan. The producer's cursor crosses its mempool/confirmed boundary; unknown native cursors fail instead of restarting at the first page. Repeated bodies, unique transaction identities, cursor exclusion, ordering, integer amounts and confirmation identities are checked.

Fresh live observations on the current private `42c2279177e94c8026c10eae63e0620bb1ea4103` API scope showed default initial pages of 50 and confirmed-only chain cursor pages of 25. Two explicit ten-row query pages were disjoint and excluded the cursor. The fixed query limit is used instead of depending on those defaults. Native HTTP responses advertise a ten-second cache lifetime; HTTP Date and request receipt time are not producer observation timestamps. This reader does not publish a new mempool freshness proof.

Each operation has one total 15-second deadline, caller/probe cancellation, and one shared HTTP socket with a four-MiB response bound. Existing address admission and separate Core pool limits are preserved. The existing address Core client verifies selected HTTP genesis, positive Signet checkpoint, actual network and independently configured Core challenge before and after acquisition. The existing Core proof responses also enforce the configured maximum index lag (`ESPLORA.MAX_BEHIND_TIP`, default two blocks) without another RPC read. Checkpoint movement, changed bodies or TCP balance disagreement fail closed. The capability probe passes its existing caller signal, including its shorter eight-second cancellation budget. Disconnect listeners are removed after both successful and failed route reads.

UTXO, scripthash and multi-summary methods remain on their existing paths. Native TCP history/UTXO limits and native REST UTXO refusal are unchanged. The original large-address history/UTXO failure evidence is retained. Successful classifier HTTP413 is distinct from recovered summary/history; large UTXO remains incomplete until an actual bounded native paging contract is available. Candidate tests and compilation do not authorize a profile change, deployment or public adoption.
