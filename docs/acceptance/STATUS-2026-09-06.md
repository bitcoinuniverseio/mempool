### The private submission surfaces stopped inventing answers

The branding and origin gates were failing on the private submission product, and what they pointed at was not a naming problem.

Every read on that surface answered a failed request with an invented one. A private broadcast that never reached a relay came back with a submission token and a status of `relayed_to_pools`. A receipt verification that performed no signature check of any kind came back `verified: true` and `signature_valid: true`. The accelerator directory was two third-party providers with third-party health endpoints. The transaction and block ordering pages substituted a fixed txid and block hash when the address named none, so they reported on the same invented transaction whatever was asked for.

None of it had a source, and a reader could not tell any of it from a real answer.

The reads now return what the API returned or they fail. The service raises a typed error naming the integration it is waiting on, the routes turn that into a 503 carrying the stage, and each surface renders the failure. Receipt validation keeps the one real check it had, the structural one: a malformed receipt is rejected with its faults named, and a structurally complete receipt is reported as unverified while there is no provider key to verify it against.

The fifteen matrix rows for those operations are now `BLOCKED` with their prerequisite named, in [current-execution-evidence.json](current-execution-evidence.json). They were `NOT TESTED`, and they are not `PASS`: the surfaces tell the truth now, which is a repair, not an acceptance.

The same `catchError(() => of(<invented value>))` pattern appears in nineteen further files under `frontend/src/app/universe`. They are listed by name in `ci-repair-2026-09-06.json` under `FIND-FALLBACK-01` so the finding is not lost.

### Four surfaces stopped reporting checks that never ran

Looking for the same pattern turned up a worse one. Four surfaces reported a cryptographic verdict that no check produced, and on each of them that verdict is the whole of what the page offers.

The AssumeUTXO snapshot verifier set its report to valid in the error handler, so a failed request rendered as "Snapshot Commitments Verified Authentic. Safe to load." The MuSig2 session verifier did the same, rendering "MuSig2 Key Aggregation Valid" with an invented aggregate key. The RGB consignment validator made no request at all: after a 450 ms timer, any input at all produced a valid result with an invented contract id and genesis txid, badged "Bitcoin confirmed". The OpenTimestamps proof verifier answered a failed request with valid, a Bitcoin block height and a block hash; its stamp returned a proof whose own bytes read mock; and two of its pages shipped invented attestations badged "VERIFIED IN BITCOIN" with no request behind them.

All four report the failure now, or report that the engine is absent, and show no verdict. The MuSig2 duplicate-cosigner check, which is real and runs locally, is unchanged.

Three further services still report a verified result from an invented fallback. They are named in `FIND-FALSEPASS-01`.

### D-CACHE-01 and D-CACHE-02

`ApiService`, `ElectrsApiService` and `LightningApiService` each carried a character-for-character copy of one request cache, with the same two faults.

The key was the function name plus the stringified arguments and nothing else, while the base path those services prefix onto every URL is reassigned by the `networkChanged$` subscription. The same call with the same arguments on two networks resolved to one entry, and the first network to ask owned the answer for the length of the window.

A failed request called `subject.error(...)` on the cached `BehaviorSubject` and left it in the map. A `BehaviorSubject` that has errored replays that error to every later subscriber, so the retry a reader asked for never reached the network.

There is one implementation now. The key carries the origin and base path captured before the request is issued, not read back afterwards from a field that has since changed, plus a per-reference function identity that a minified name cannot make collide. A failure evicts its own entry, and only its own, so the error reaches the callers waiting on it and the next call is a real request. Same-network coalescing is unchanged.

Nine cases cover it, and four of them fail against the algorithm being replaced. Evidence and the failing-first result are in [request-cache-2026-09-06.json](request-cache-2026-09-06.json).

This is local component evidence. It establishes the cache, not a read. The browser half of the check, a real read on two networks with the displayed source and checkpoint compared across a switch and a reload, needs the changed Explorer overlay to be reachable.
