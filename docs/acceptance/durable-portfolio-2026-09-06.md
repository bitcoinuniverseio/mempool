## Repairs

P16 file selection previously retained a valid pending backup after the user selected malformed JSON. Clicking **Validate and import** could therefore import the older file despite the rejection message. An older asynchronous file read could also replace a newer selection, and file-read failures were unhandled. The file selection now clears the pending backup immediately, accepts only the latest completed read and reports read failures. Four UI/component regressions reproduced these failures before the repair and pass after it.

P14 passphrase replacement previously saved the new vault metadata before re-encrypting records in separate transactions. P16 import cleared records and then inserted replacements and metadata in separate transactions. Interrupted writes could leave mixed keys or partial data. Both operations now prepare encryption before opening one IndexedDB transaction containing the complete record change and matching verifier/metadata. The active in-memory key changes only after that transaction commits. The common transaction helper catches synchronous write errors and aborts queued writes. Settings reports an unsuccessful passphrase change without losing the current key.

Backup import also rejects empty record collections that cannot prove their passphrase, duplicate/missing record IDs, missing record types, unknown KDF names and malformed decrypted JSON before replacing anything. Previously exported nonempty version-1 Argon2id/PBKDF2 backups keep their existing format. No KDF, encryption algorithm or live default changed.

Independent review reproduced a second vault defect: a write completing while passphrase derivation was paused could be omitted from the rotation snapshot, leaving old-key ciphertext under the new metadata. Updating an existing ID could instead lose the newer value. The vault now serializes complete operations, including the snapshot, cryptography and commit. Reads and encrypted exports share this queue so they cannot combine different key/record generations. A put already encrypting is drained before rotation; later inserts, same-ID updates and deletes run after it with the correct key. Lock is immediate, invalidates pending work with a generation counter, cancels pending worker derivation and aborts active write transactions. Late rotation/import/unlock/create results cannot restore a cleared key. Terminal transaction events release the queue, including failure paths. The independent reviewer found no remaining actionable race or nested queue deadlock in this bounded implementation.

The offered manual-only portfolio promised user-entered positions, but its existing `manualEntries` schema had no editor or report reader. The overview now exposes real add/edit/remove controls and persists through the existing encrypted portfolio store. Quantities and optional unit prices remain decimal strings; BigInt multiplication preserves values beyond JavaScript's safe-integer limit without rounding. Asset/liability, explicit price currency and effective date are retained. Every entry remains `authority: user` and `includedInCombined: false`. The report shows a separate manual section and actual CSV rows with exact amounts, explicit user-entered source and unpriced state. Manual positions do not enter address-derived totals, allocations, feed claims or encrypted shares. Currency labels are not exchange rates, and USD/EUR estimates are never summed.

The first populated-manual report test failed against the prior absent preview, then passed after the repair. Review also found two issues in the newly reachable UI: hiding privacy while editing retained real input values in the DOM, and spreadsheet formula prefixes in manual labels were only CSV-quoted. A failing-first DOM test and seven failing-first export cases now pass. Privacy removes the form DOM, clears the draft and rejects hidden edits/saves.
