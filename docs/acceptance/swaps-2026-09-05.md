## Implemented behavior

- Backend and frontend seeded swaps, fake provider identity/signature/health, fabricated volume, uptime, confirmations, settlement reconciliation and truncated PSBT strings are removed. An HTTP failure reaches the UI as an error.
- A public request carries `?chain=bitcoin&network=signet` (or another explicit Bitcoin network). Omitting both parameters means Bitcoin mainnet; partial or invalid context is rejected. The public package must agree with that context. The existing configured singleton node must have the same configured network **and** report the expected network through `getblockchaininfo`.
- The on-demand node adapter checks actual serialized transaction identity, explicit output index, active block membership, current UTXO status including mempool spends, confirmations and a stable tip before answering. It never accepts a caller height or URL. Concurrent node reads are bounded to one per adapter. It reuses the existing Bitcoin RPC client and its configured timeout; no separate node poller or instance was introduced.
- The implemented script adapter covers only Bitcoin two-leaf Boltz submarine/reverse Taproot contracts. It reconstructs claim/refund leaves, validates curve points and address/output commitment, verifies the actual value and produces an unsigned PSBT with non-witness/witness prevout data, refund tapscript/control block, version 2, absolute height locktime, sequence `0xfffffffd` and the requested single destination/fee. Generation does not sign or broadcast.
- For confirmed single-input/single-output spends, the adapter checks the referenced outpoint, chosen script/control path, SHA256 preimage relation for claims, refund locktime and sequence, exact destination/fee commitments and BIP340 Schnorr signature with default or ALL sighash. Unsupported key-path, annex, multi-input, multi-output and other proof formats remain unverified.
- Provider identity, provider release revision, signed-manifest schema, cooperative cancellation and offchain settlement have no authenticated owned integration. A present key/signature or caller `claimed` status never establishes those facts. The four existing protocol catalog entries remain visible with explicit scope/provenance limitations. Liquid/Ark static Active/Pilot claims and reverse-swap zero-risk wording were removed.
- The new `swaps-observations.ts` adapter reuses `intelligence_events`, partitions identity by chain/network/txid/vout, upserts actual public check metadata and reads it after a process restart. Payload hashes use stable key ordering. Database errors remain visible; there is no in-memory success fallback. Stored observations describe their recorded checkpoints and are displayed as historical, never current settlement/spend state. No global swap-volume claim is derived from partial checks. A live durable restart/reorg journey is still blocked below.
- Follow-up review rejects a missing or malformed UTXO RPC result instead of treating it as an unspent output. The browser independently checks the exact refund key/script, control-block Merkle proof/parity, internal key, lockup address/output script, complete previous transaction identity, supported sighash and mature checkpoint before enabling export. A leaf's presence alone is insufficient. Pending file imports are discarded after edits, network changes or component destruction; file-read errors remain visible.
- Recovery UI accepts/imports bounded public JSON, destination and integer fee, requests first-party evidence, shows invalid/unavailable/waiting/spent/success states, independently decodes artifacts with the existing `@scure/btc-signer`, and supports copy/raw `.psbt` download. Backend serialization uses `bitcoinjs-lib`, so browser decoding is independent. Inputs and packages are not put in URLs, analytics or browser storage. Changes/network switches cancel pending results. All swap navigation preserves the selected route network.
- The inspector now has functional local public-package validation and an explicit first-party chain-verification action. Private backup fields are rejected before transmission. Local structure checks never claim signature or chain validity.
- The previously inactive simulator runs a local, labeled common-ancestor rollback scenario. It computes remaining confirmations and the absolute-height refund condition before replacement blocks arrive. Its fee comparison is explicitly hypothetical and never predicts actual mempool eviction. Simulation output is not sent to the evidence API.

- [Submarine claim and refund leaves](https://github.com/BoltzExchange/boltz-core/blob/a932d49c4daaeae3d7940dc1519bf77ef92e6dc1/lib/swap/SwapTree.ts).
- [Reverse claim leaf and shared refund leaf](https://github.com/BoltzExchange/boltz-core/blob/a932d49c4daaeae3d7940dc1519bf77ef92e6dc1/lib/swap/ReverseSwapTree.ts).
- [Taproot leaf and control-block construction](https://github.com/BoltzExchange/boltz-core/blob/a932d49c4daaeae3d7940dc1519bf77ef92e6dc1/lib/swap/TaprootUtils.ts).
- [BIP65 absolute locktime semantics](https://github.com/bitcoin/bips/blob/master/bip-0065.mediawiki).

These references establish the supported **script format**, not an authenticated current provider deployment, the catalog's old version strings, an owned Signet integration or provider API support for Signet.
